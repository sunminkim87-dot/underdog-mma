# P0 검증 결과

검증 날짜: 2026-11-13 (클라이언트 기준 날짜). 엔진: Godot 4.6.3 stable official, Linux x86_64.

## 자동 로직 테스트

`tests/test_core.gd`: **4,707개 검사 통과, 실패 0**.

- 18세 시작·3개 스타일 보너스·정확히 4주 진행·12개월 후 나이 증가.
- 기본 월간 현금 100 → 84만원, 피로 10.8, 능력 성장과 상한.
- 휴식 효과·피로에 따른 성장 저하·자금 부족 시 상태 불변·무자금에서 알바로 회복.
- 첫 경기 개방·3개월 재출전 제한·수당과 전적 단일 지급·동일 시드 재현·입력 상태 비변경.
- 저장/불러오기·전체 경기 로그 보존·손상된 주 저장의 백업 복구·복구 후 재저장·잘못된 필드/미지원 버전 거부·쓰기 실패 반환.
- 150개월 훈련·경기 반복·유효 저장 스키마·120개 이력 제한·재귀 이력 복제 방지·저장 크기 검사.

시드 고정 경기 표본 **6,400회**: 스타일 조합 4,500회 + 피로 비교 1,400회 + 전략 비교 500회. 일반 기능·장기 진행 테스트의 추가 경기는 이 표본 수에 포함하지 않았다.

스타일 표본 4,500회에서 KO/TKO 117회, 서브미션 934회, 판정 3,449회. 평균 경기 길이 약 813초. 동일 조건 700회에서 피로 0인 선수 승리 295회, 피로 100인 선수 승리 70회로 피로의 실질적 영향 확인. 상세 분포는 `tests/core_results.json` 참조.

표본은 오류와 기초 분포를 검증한다. 선수 측은 균형 전략, 상대 측은 스타일 전략을 사용하므로 스타일 승률 표를 대칭적인 우열표로 해석하지 않는다. 최종 상성·경제 밸런스는 플레이 테스트 후 조정해야 한다.

## 실제 렌더링 UI 테스트

`tests/test_ui.gd`: **391개 검사 통과, 실패 0**.

Linux Xorg dummy + Mesa llvmpipe OpenGL Compatibility에서 실제 렌더링. 버튼 신호와 선택 변경을 자동 호출하여 생성 → 2개월 일정 → 경기 → 결과/기록 → 수동 저장/불러오기 → 씬 재시작 자동 불러오기 검증. 빈 이름, 월 진행 취소, 새 게임 취소, 훈련 선택 저장, 사용자 프리셋, 출전 버튼 잠금, 화면 너비와 카드 글자 배치도 검사.

540×960 창과 360×800 창에서 확인하고 **스크린샷 7장** 저장. 실제 손가락 터치·Windows 마우스 입력·Android 키보드/안전 영역은 이번 테스트에 포함하지 않았다.

## 배포 확인

- 공식 Godot 4.6.3 Windows release x86_64 템플릿으로 `.exe` 내보내기 성공. 템플릿 ZIP에서 추출한 항목의 크기와 ZIP CRC32 확인.
- PE32+ x86-64 GUI 실행 파일 형식 확인. 게임 데이터·폰트·SVG·스크립트를 내장 PCK에 포함.
- 동일 프로젝트의 Linux release 템플릿 내보내기와 headless 실제 실행 성공.
- 클린 프로젝트 재가져오기 및 로직 테스트 결과와 배포 ZIP 무결성은 `BUILD_VERIFICATION.txt`에 기록.
- 소스 최종 로직/UI 테스트 로그에서 스크립트 오류 없음. UI 검증 환경의 V-Sync 미지원 경고 1종은 가상 화면 드라이버의 제약이다. 오디오는 Dummy 드라이버로 검사했다.

## 검증하지 못한 항목

Windows OS에서 `.exe`를 직접 실행하는 네이티브 테스트는 이 Linux 환경에서 수행하지 않았다. 따라서 Windows 실행 파일은 내보내기·형식 검증을 마친 첫 테스트 빌드이며, 사용자의 Windows에서 실행 확인이 필요하다. Windows 배치 테스트 도우미도 코드 검토만 수행했다.

Android APK 생성·서명·실기기·스토어·기기별 그래픽 드라이버, 실제 정전/강제 종료의 모든 시점, 운영체제별 파일 권한과 보안 프로그램 동작은 검증하지 않았다.
